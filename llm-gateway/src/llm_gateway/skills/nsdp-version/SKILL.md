# 查询版本信息

使用 NSDP MasterPlan 核对会议中的版本、车型、里程碑和 Gate 日期。查询依据是实时工具结果，不使用记忆或会议上未经核实的日期作为版本计划事实。

## 查询方式

调用 `meeting_nsdp_lookup_release`，以 `release` 参数传入会议中识别出的版本号，例如 `BL1.5.0`。工具使用组织者的授权，通过 `noam nsdp releases --release BL1.5.0` 查询；不要自己读取 token 或调用命令行。

该参数是**不区分大小写的子串过滤**，不是精确版本匹配。先从结果中确认完整版本名，再结合会议中已明确的车型、平台等信息辨别对应记录；不能把相近版本或不同车型的 Gate 当成同一条计划。一次讨论多个版本时分别查询。

## 如何处理结果

1. 优先查找与当前讨论对应的版本及车型，再读取相关的里程碑名称、日期和阶段。车型或版本有多个可能匹配且无法从上下文确定时，说明存在歧义，不要任选一条。
2. 如会议给出了 Gate 日期，比较对应 Gate 的实际计划日期与会议表述；能确定一致时无需为了复述而主动打断，不一致且有必要时简短指出版本、Gate、会议表述及查询结果。
3. 没有查到版本、目标 Gate 或日期时，说明查询结果不足；日期为 TBD、空值或缺少年份时保持原样，不推断或编造。不要把查询失败当作版本不存在。
4. 工具返回 `authorization_required`、`timeout`、`unavailable`、`empty` 或其他错误时，不假称已核对；如当前问题需要答复，简要说明暂时无法核实。授权通知由系统处理，不索取或显示 token。
5. 根据会议信息和当前问题决定是否发言；回答应简洁，并遵守系统要求的结构化决定和字幕证据约定。
