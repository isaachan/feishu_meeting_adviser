# 飞书静音检测与门控调研（5.12）

状态：2026-11-10 调研完成，方案定稿（代理静音为主 + 像素校验），**实现 pending**。
背景：隐私硬需求——用户在飞书静音期间，本机麦克风音频不得采集/转写（plan.md 5.3/5.12）。首版（2026-11-09）曾降级为仅手动开关；本文记录自动检测的完整探索与选型依据。参考对照：`~/Downloads/meeting-asr-subtitle`（Windows 客户端，UIA 读取参会人/悬浮窗按钮的 accessible name，已验证可用）。

## 环境

- macOS 26.6（MacBook Pro，Apple Silicon），飞书 7.x（Electron，主进程 `Feishu` + 会议独立进程 `Feishu Meetings`/`Lark Helper (Iron)`，同 boundis 孪生窗口）
- 用户配置的会议内静音快捷键：`⌘⇧D`（**仅会议进程聚焦时生效**，非全局；快捷键可被用户改配，产品需可配置）
- 所需系统权限：辅助功能（事件注入/AX）、屏幕录制（截屏）

## 通路一：AX 无障碍（UIA 等价）——不可行 ✗

Mac 上对等的方案是读会议窗口 AX 树中麦克风按钮的 label（Windows 参考实现读「打开麦克风」=静音 /「关闭麦克风」=开麦）。实测结论：

- 会议进程窗口只暴露 `AXWindow → RootView` 两级空壳（带 `ChromeAXNodeId`/`AXDOMClassList` 桥属性但无内容）。
- 唤醒属性均被拒：`AXManualAccessibility` → -25205；`AXEnhancedUserInterface` → -25208（列入属性表、`IsAttributeSettable=True` 但 set 失败；置前 + `AXRaise` 后仍失败）。
- 对照组：飞书**主进程**窗口（日历页）渲染树完整（`AXWebArea`、带中文 label 的按钮）——说明是会议子进程特意禁用了渲染器无障碍。
- 带 `--force-renderer-accessibility` 重启会议进程理论上可唤醒，但产品上不可接受（需控制用户会议客户端的启动方式）。

结论：**Mac 会议进程的 AX 树不可用，此路不通**；Windows 移植时 UIA 通路仍可按参考实现复用（5.8 复核）。

## 通路二：像素色彩读取——信号存在但脆弱，降级为校验器 ⚠

UI 形态（用户实测口述）：工具栏最左麦克风按钮，静音=红色+左上→右下斜杠；开麦=灰色，说话时绿色填充随音量增大（顺带可作飞书侧 VAD）。

已验证的正面结果：

- 纯净管线（v3：窗口 ID 截取 + BGRA→RGB + 多窗取强信号帧）在悬浮迷你窗（256×80）上**连续数分钟稳定跟踪**：静音 red≈3388 / 开麦 red≈0，切换即时。
- 主窗口（800×645）在可见状态下也准确跟踪过 3 次切换（red 2301/28 ↔ 2019）。

实证缺陷（不作主判的原因）：

| 缺陷 | 实测表现 |
|---|---|
| 遮挡=冻结画面 | 主窗被完全盖住后，截屏 API 返回**跨 30 分钟字节级不变的旧帧**（red=816 恒定）——对隐私门控是致命风险（冻结的"开麦"读数会让静音期继续采麦） |
| 迷你窗间歇黑帧 | 同一窗口 ID 时而正常时而 bright=0 |
| 孪生窗口 | 有名/无名两窗同 bounds，z 序随焦点抖动，单窗挑选不确定 |
| 内容污染 | 参与者胶片条的红色静音徽标、红色视频内容都会污染"区域数红"（曾把胶片条徽标误判为静音） |
| 工具栏自动隐藏 | 鼠标离开窗口即隐藏（主窗/迷你窗皆然），需 hover 唤醒（有限频、还原光标） |
| 通道序陷阱 | CoreGraphics 截图字节序为 **BGRA**，按 RGB 分析全军覆没（曾把红按钮判成蓝） |

工程缓解已验证：多窗全截取"信号最强帧"解决孪生抖动；连通块（膨胀合并+尺寸/实心度/位置）可区分按钮与徽标；`NSEvent.mouseLocation` 做光标还原（注意 `CGEventGetLocation(None)` 返回 (0,0) 的坑）。

## 通路三：代理静音（CGEventPostToPid）——定稿主通路 ✓

工具代发静音快捷键，状态由工具自身权威记录：

- `CGEventPost(keyDown/keyUp + cmd/shift flags)` 需会议进程聚焦才生效；聚焦+还原方案可行但会短暂抢焦点（窗口弹到前台）。
- **`CGEventPostToPid(event, 会议进程pid)`：静音翻转成功、零焦点扰动**——直接投递进程事件队列，绕过"需聚焦"限制。已多次实测确认。

## 定稿设计（待实现）

```
MuteGate 状态机：
  UNKNOWN（启动/入会）   → 隐私默认：不采集麦克风
  工具 mute   → PostToPid ⌘⇧D → MUTED   → 停采（gap 显式断句）
  工具 unmute → PostToPid ⌘⇧D → UNMUTED → 恢复采集
  像素校验（尽力而为，低频轮询）：
    · 与工具状态不符（用户直点飞书按钮/主持人强制静音）→ 采纳像素读数 + 记录
    · 像素不可读（遮挡冻结/黑帧/无会议窗）→ 沿用工具状态，标注 degraded
```

- 快捷键可配置（用户当前 `⌘⇧D`）；会话开始建议做一次**自检闭环**：工具自行 toggle 一次并用像素确认读数一致后回拨。
- 手动开关（`--mic`）保留为兜底；自动门控叠加其上；外部变更（host-mute）依赖像素纠偏，纠偏不可用时接受窗口期并在诊断中说明。
- Windows 移植（5.8）：优先复用参考项目的 UIA 读取（可作主判），代理静音（SendInput）与像素为备选。
