# 产品需求 · v0.1（草案）

状态：设计基线，随实现冻结。人物与场景是本文的核心；实现细节见 [ARCHITECTURE](ARCHITECTURE.md)。

## 1. 产品定位

会参谋在会议进行中为**组织者**提供实时辅助（听会 → 理解 → 判断是否需要补充或回答），并按组织者的**显式授权**把辅助结果分发给参会者。组织者是会议数据的拥有者：录音、字幕、AI 回答的可见范围由组织者一人决定。

## 2. Personas

### 小A —— 会议组织者（主持人）

- 有飞书账号；目标会议在她的日历上，且**她是该日历事件的组织者**（准入校验条件）。
- laptop（Mac 先行，Windows 跟进）上装两个东西：飞书客户端、会参谋采集器（recorder app）。
- 做过一次飞书 OAuth 授权（用于选会议与身份核验），此后免打扰。
- 期待：开会时像带了一个不出声的参谋，该提醒的提醒、该回答的回答，都发到飞书私聊里。
- 权限：批准/拒绝参会者的订阅申请；随时撤销；让 bot 暂停/恢复辅助。

### 小B —— 普通参会者

- **只装飞书，什么都不装**，不部署任何东西。
- 通过与"会参谋 bot"单聊表达诉求；收到的内容由小A 的授权决定。
- 明确不能做的事：驱动 AI（提问、改变模型行为）、获取授权范围之外的内容（如完整字幕、录音）。

## 3. Scenarios

### S1 · 首次准备（小A，一次性）

1. 小A 在 laptop 安装采集器，完成飞书 OAuth 登录（浏览器本地回调，凭据只存本机）。
2. 会议开始前，小A 在采集器里看到"当前时间窗内我组织的会议"列表（来自飞书日历，非组织者的会议不可选）。
3. 小A 选中会议，开始采集：远端声音（系统播放回路）默认开启；本机麦克风默认**关闭**，需显式打开（隐私优先；小A 在飞书静音期间不该被采集的话，不进链路）。
4. 整场原始音频在本地留存（排障/重转写用），不上传。

验收口径：未授权/非组织者/超时间窗的会议无法开始采集（与旧 stt-server v2 授权语义一致）。

### S2 · 会中辅助（小A 的主链路）

1. 采集器把双路音频持续上行到云端 advisor（约 64 KB/s）。
2. 云端转写为字幕 → 进入该会议的会话上下文 → 模型判断是否需要发言。
3. 需要时，会参谋 bot 把回答（LLM reply）以飞书私聊发给**小A**。
4. 小A 可对 bot 说"暂停辅助 / 恢复辅助"（暂停期间仍转写、不发回答）。

验收口径：说完一句被回答的话 → 小A 飞书收到回答，全链路 P95 时延预算 ≤ 20 秒（旧目标沿用，待端到端实测修订）。

### S3 · 参会者订阅（小B + 小A 审批）★ 核心新场景

前置：小B 在飞书里能找到会参谋 bot（应用可被发现/可添加）。

1. **申请**：小B 给 bot 发消息："你好，我想收到会议 123456789 的信息"。
2. **校验**：bot 解析 9 位会议号，在云端注册表里查找"正被服务中的会议"：
   - 命中且会议进行中 → 生成订阅申请（状态 `requested`）；
   - 未命中 / 已结束 → bot 回复小B"未找到该会议或会议已结束"。
3. **审批**：bot 给小A 发私聊："小B 请求接收会议《标题》的会参谋回答，回复『同意 #rN』或『拒绝 #rN』"。
4. **小A 回复**：
   - 同意 → 订阅置 `approved`，bot 回执双方；**从下一回答起**，小B 与小A 同时收到 LLM reply。
   - 拒绝 → 订阅置 `denied`，回执小B。
5. **撤销**：小A 随时对 bot 说"撤销 小B 在《标题》的订阅"→ 置 `revoked`，此后小B 不再收到。
6. **重复申请幂等**：已 `approved` 再申请则提示当前状态，不新建；`denied` 后再申请需小A 重新审批（按新申请处理）。

边界（显式约束）：

- **仅前向**：批准只对之后新产生的回答生效，不回溯历史回答。
- 小B 收到的是**会参谋的回答**，不是完整字幕或录音。
- 小B 的任何消息都不进入模型上下文、不触发模型调用。
- 审批请求不承诺可靠投递（bot 离线期间小B 的申请会丢，小B 重发即可）；已批准的分发走 outbox，可靠。

### S4 · 会中问答与控制（小A）

小A 对 bot 的指令集（v1 全部走私聊文本）：

- `暂停辅助` / `恢复辅助`
- `同意 #rN` / `拒绝 #rN`（审批）
- `撤销订阅 <小B> <会议号>`
- `状态`（当前会议的采集/模型/订阅概况）

### S5 · 收尾与异常

- **正常收尾**：会议结束，小A 停止采集（或按时长自动停）；云端把该会话排空（在途字幕、模型任务、待发回答全部落定）后置 `ended`。`ended` 后的新订阅申请一律拒绝。
- **网络断线**：采集器本地缓冲、恢复后重传；断线期间未完结的语句丢失（与旧 STT 契约语义一致）。云端对已收到的输入照常处理。
- **laptop 合盖/退出**：等同断线且不自动恢复；云端继续处理已收到的输入后排空。
- **云端不可用**：采集器本地持续留存音频（证据在手），字幕丢失不补（v1 不做事后重转写，列为后续增强）。

## 4. 范围与非目标

**v1 范围**：S1–S5 全部；单云端部署（内网/受信网络）；同一组织者的多场会议并发；多个组织者共用部署（数据按用户隔离，鉴权为首日需求）。

**非目标（v1 明确不做）**：

- 小B 驱动模型（任何形式的问答）。
- 批准后回溯历史回答。
- 群聊内 @bot 问答（旧 chatbot demo 能力，不带入）。
- 即时会议（无日历事件）的采集与订阅。
- 多设备对同一会议双录、字幕合并。
- 公网匿名注册开放（部署受信边界内运营）。
- 录音/字幕的会后产品（妙记类能力）。
