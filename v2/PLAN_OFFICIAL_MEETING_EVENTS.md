# 会中字幕官方接口优先接入计划

状态：v2 为唯一当前方向，持续采集已在一场授权会议中完成脚本对照；跨会议稳定性、完整性与端到端时延仍待验收。**路线决策：使用应用身份 + 配置 9 位会议号调用官方 `bots/join` 入会并获得内部 `meeting_id`。v1 虽可能更快，但缺少说话人信息、上下文不足，已放弃且不作回退；原计划中的用户 OAuth / `user_active_meeting` 不是当前脚本的执行步骤。**当前操作与测试步骤见 [v2 README](README.md)，当前待办见 [TODO](docs/TODO.md)。依据：2026-10-08 版 [v1 PRD](../v1/docs/PRD.md)、[v1 技术设计](../v1/docs/TECHNICAL_DESIGN.md)、[v1 TODO](../v1/docs/TODO_2026-10-08.md)，以及用户转述的字节员工消息；**接口能力、权限、字段和灰度条件均为线索，不等于已由本项目实测或获得官方承诺**。

## 评估与决策

> v1 的 TODO 中“没有满足需求的官方 API”是旧方案当时的判断，未留存官方依据；本计划以新线索重新验证，不将该旧判断作为结论。

- PRD 的硬要求是会中获得内容并在会中回答；`transcript_received` 会中事件提供带说话人的输入，不必录制、解析 `.vemedia` 或自行 ASR。**原 6 秒目标撤销，当前目标为提问结束至参会者看到首段有效回答 P95 ≤ 20 秒**；2026-10-14 用户确认先完成功能，再优化性能，20 秒暂不阻塞首版功能验收；完整消息一次发送，发送与展示也计入时延。
- 当前选择**已入会机器人 + 应用身份事件轮询**；通过 `bots/join` 使用 9 位会议号入会并取得内部 `meeting_id`，不执行用户 OAuth / `user_active_meeting`。v1 `.vemedia` + STT 不再作为备选或自动降级，历史代码与测试只存档。
- 当前候选链路：App ID/Secret 换 `tenant_access_token`，通过 `POST /open-apis/vc/v1/bots/join` 传 9 位会议号及可选密码入会，用其响应的 `data.meeting.id` 调用 `GET /open-apis/vc/v1/bots/events?meeting_id=<meeting_id>`；筛 `meeting.activity` 事件的 `payload.activity_event_type=transcript_received`。官方 [join](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/vc-v1/bot/join.md) 和 [events](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/vc-v1/bot/events.md) 文档明确支持应用 token 且处于灰度，真实租户仍待验收。原用户路线为 `user_access_token` → `GET /open-apis/vc/v1/bots/user_active_meeting` → `bots/events`，当前不运行。
- `speech_to_text/v1/speech/stream_recognize` 需要自行提供 PCM，不是会议字幕源；`minutes/v1/minutes/{minute_token}/transcript` 用于会后完整逐字稿，不作为会中输入。应用身份路径要求机器人入会，不能承诺“别人看不到机器人”；如需无机器人入会再评估用户身份 OAuth 路线。

## 阶段 0：接口与准入验证（先做，阻塞项）

1. 根据官方 `bots/join` 和 `bots/events` 契约核对 token、`vc:meeting.bot.join:write`、灰度、`page_token`、留存、错误码及字幕字段；记录来源和核验日期。接口有文档不等于目标租户已开放。
2. 用 App ID/Secret 获取 `tenant_access_token`；获同意的测试会议中，主持人开启 AI 总结与允许智能体入会，在 `config.yaml` 配 9 位会议号和可选密码，运行 `stage0.py join`；只将成功入会响应的 ID 写本地忽略的 `session.yaml`。凭据及完整文本不得进仓库。
3. 会中运行 `stage0.py probe` 做单次有界探测；核对嵌套的 `transcript_received_items` 字段、分页与异常，分别验证 bot 未入会、无权限、过期 token、会议结束/切会。记录脱敏结果。未通过前不宣称方案已可用。

**G0 基础可行性已通过：** 当前租户的一场测试会议中，应用机器人成功入会、连续读取带说话人的字幕，且远端能在会中看到机器人发的文字，因此可进入阶段 1。该门槛不等于多场可靠性、异常恢复或 20 秒目标已通过；后续仍按 [0.6](docs/TODO.md) 复测，不回退 v1。

- 实现固定范围逐页扫描、重叠窗口、周期回扫、结构化错误、token 刷新、可中断恢复、会议生命周期与操作锁。无法核实的恢复区间保留完整性风险，不静默跳过历史。

## 阶段 2：真实时延与业务验收

1. 在授权会议中让远端参会者说出可标注的短问句，记录提问结束、字幕可用、Agent 开始有效回答的时间；另记接口请求/返回及 AI 处理时刻。跨设备对齐时钟，报告测量误差。比较不同轮询间隔（以官方限流为约束）的中位、P95、最大值及漏句；验证长句何时形成、专有名词和中英混说质量。字幕只在句末到达时可能天然增加等待，不能拿“轮询很快”代替端到端证据。
2. **先于问答实现，继续验证会中输出**：官方[发送会中消息](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/vc-v1/bot/message.md)支持已入会机器人发送 `text`/`reaction`，须额外获得 `vc:meeting.message:write` 且仍处于灰度；用户已确认单条文本发送成功、远端参会者能在会议内看到机器人署名的消息；其他会议适用范围与送达延迟仍待验收，不能直接称为专门的 comment 功能。文档未给该接口语音类型；IM 音频消息不等同于会议发言。首版不提供固定唤醒词或特殊控制指令，由行为文档和 LLM 根据上下文决定发言/沉默及自然语言控制意图，会中 comment 文字一次完整发送；仍需明确暂停/完整停止、控制权限、取消与结论修正的行为边界；若会中消息后续在目标范围不可用或体验不合格则再选独立界面，不自动使用未证实的语音能力。调研见[会中输出](docs/MEETING_OUTPUT_RESEARCH.md)。
3. **首版功能通过门槛：** 在多场、含远端发言的会议中验证 LLM 按行为文档自主参与、上下文与自然语言控制、入会介绍和真实会中完整回复，无不可解释漏句与重复回复；完成资料告知和停止/删除机制核对。用户在功能完成后提供对话脚本并确定样本/质量口径。提问结束至首段有效回答可见的 P95 ≤ 20 秒作为后续性能优化目标，暂不阻塞功能验收；功能结论与性能结果分别记录。详细决定和待补边界见[阶段 2 交互口径](docs/STAGE2_INTERACTION.md)，不回退 v1。

## 待确认/风险清单

- 灰度功能、组织策略和会议主持人设置可能使可用用户面受限；应用权限不等于 bot 已入会，也不等于可绕过会议知情/隐私要求。上线前明确参会者告知、数据最小化、保存期限、撤销授权和删除机制。
- 员工说明没有给出事件留存、游标语义、实时字幕生成前置条件及端到端 SLA；这些都须通过文档 + 实测确认。应用身份路线需机器人入会，产品上也须明确助理正在读取会议内容。
- 如果机器人未入会或会议未启用相关能力，应明确不可用，不静默切到本地录制 hack；备选路线须单独获得用户确认及合规评估。
