# 会中字幕官方接口优先接入计划

状态：待官方文档核验与真实会议验证。依据：2026-10-08 版 [v1 PRD](../v1/docs/PRD.md)、[v1 技术设计](../v1/docs/TECHNICAL_DESIGN.md)、[v1 TODO](../v1/docs/TODO_2026-10-08.md)，以及用户转述的字节员工消息；**接口能力、权限、字段和灰度条件均为线索，不等于已由本项目实测或获得官方承诺**。

## 评估与决策

> v1 的 TODO 中“没有满足需求的官方 API”是旧方案当时的判断，未留存官方依据；本计划以新线索重新验证，不将该旧判断作为结论。

- PRD 的硬要求是会中获得内容并在会中回答；员工描述的 `transcript_received` 会中事件若可用，直接满足输入需求，不必录制、解析 `.vemedia` 或自行 ASR。轮询不等于推送，能否满足已确定的 **6 秒提问结束到开始有效回答**目标仍要实测。
- 将**用户身份官方事件轮询**升级为首选输入路线（有条件决策），`.vemedia` + 本地/云端 STT 保留为实验备选，不再把阿里云 STT 实现作为主线前置任务；已完成的文件解析、解码和本地 STT 代码与测试不删除。
- 员工消息给出的接入链路：以 `user_access_token` 调用 `GET /open-apis/vc/v1/bots/user_active_meeting` 获取长数字 `meeting_id`，再调用 `GET /open-apis/vc/v1/bots/events?meeting_id=<meeting_id>`，筛选 `transcript_received`，通过 `page_token` 增量轮询；声称需权限 `vc:meeting.meetingevent:read`、用户本人在会、会议开启“允许智能体入会”（可能需先开启“AI 总结”，且受灰度/客户端版本影响）。**逐项以官方文档、控制台和真实账号验证；不要仅凭路径或 HTTP 200 认定可用。**
- `speech_to_text/v1/speech/stream_recognize` 需要自行提供 PCM，不是会议字幕源；`minutes/v1/minutes/{minute_token}/transcript` 用于会后完整逐字稿，不作为会中输入。应用机器人读事件需要机器人入会；首版优先用户身份，不把 bot 入会当成前提，也不承诺所有参会者都不可见任何产品使用痕迹。

## 阶段 0：接口与准入验证（先做，阻塞项）

1. 查飞书开放平台这两个接口的**准确文档链接和契约**：请求参数（尤其 `page_token`、分页大小）、响应结构及 transcript 字段、token 类型、scope、是否有独立的应用/用户授权及管理员审核、限流、事件保留窗口、空页/游标语义、错误码、会议结束行为。记录核验日期及文档版本；网页能打开不等于响应内容核验成功。
2. 建立测试应用并申请最小权限 `vc:meeting.meetingevent:read`；走 OAuth 获取并安全保存/刷新 `user_access_token`。测试账号加入自己有权使用的会议，核对开关（含灰度、客户端版本、主持人/管理员权限）；记录无法启用时的产品降级提示。不得在日志中记录 token、完整会议文本或未授权成员资料。
3. 用两个账号的**获同意的真实会议**试验：参会者 A 的用户 token 调用两接口，验证拿到的是内部 `meeting_id`（非 9 位会议号），产生 `transcript_received`；确认本人未入会、无开关、无权限、token 失效以及切会时的表现。验证发言人、语言、文本、起止时间、`sentence_id` 的实际类型、单位与缺失情况；记录必要的脱敏响应样例。没有测试通过前不宣称方案已可用。

**通过门槛：** 会中能稳定获取新发言文本，所需用户/应用授权及会议设置可由目标试用群体实际完成；否则暂不切换主输入，回退现有 `.vemedia` 路线并标明原因。

## 阶段 1：最小增量采集器

- 定义 `MeetingTranscriptSource` 边界：启动/停止、当前会议标识、规范化的确认字幕事件、错误/状态事件；与文件/STT 源向下游使用同一语义。官方字幕先按**已确认句子**处理，不凭空生成 `partial`；如实际接口提供修订，再按文档设计更新语义。
- 获取当前会议并在轮询中检测离会、切会、会议结束；为每个 `meeting_id` 单独维护游标和去重状态。初次启动是从头回放还是只读新事件、空页是否继续使用原游标、是否允许持久化游标，均先依据接口契约确定并写测试，不臆测 `page_token` 行为。新页按接口顺序处理、成功处理后提交游标；重启/超时允许重复但不得漏句，按实际字段组合（会议 ID + `sentence_id`，必要时补充事件 ID/时间）幂等。
- 分页追赶与持续轮询分开：有下一页时按文档继续取；无新事件时以可配置间隔轮询并计入配额。处理 429、5xx、网络错误（退避/抖动、可恢复）、401/403（重新授权或提示，无限重试禁止）、游标过期（提示内容缺口与受控重新同步）；不把聊天/进出事件当字幕。建立脱敏指标：请求耗时、轮询间隔、重复/缺口、错误、最近字幕年龄、会议切换。
- 测试使用脱敏的真实响应 fixture + 假客户端/可控时钟，覆盖分页、空页、重复、乱序/修订、缺字段、重新启动、限流、token 过期、会议切换；只有通过真实会议验证后才写生产客户端。OAuth 凭据不能写入仓库或测试 fixture。

## 阶段 2：真实时延与业务验收

1. 在授权会议中让远端参会者说出可标注的短问句，记录提问结束、字幕可用、Agent 开始有效回答的时间；另记接口请求/返回及 AI 处理时刻。跨设备对齐时钟，报告测量误差。比较不同轮询间隔（以官方限流为约束）的中位、P95、最大值及漏句；验证长句何时形成、专有名词和中英混说质量。字幕只在句末到达时可能天然增加等待，不能拿“轮询很快”代替端到端证据。
2. 首版先选定**用户明确唤起 + 独立界面文本回答**为可验证的临时方案（产品仍须确认）；支持暂停/恢复/取消，核对结论修正、非唤起不回应及参与状态可见。会议内语音或消息输出另行评估权限、可见性及回流，不由输入接口自动解决。
3. **通过门槛：** 在多场、含远端发言的会议中无不可解释的漏句；用户可完成准入；提问结束至开始有效回答满足 6 秒目标的验收口径（需与产品确认 P95/样本量）；安全与隐私审查通过。若延迟或覆盖不达标，先排查字幕生成/轮询/模型各段瓶颈，再决定优化、采用备选音频/STT 或调整产品目标，不隐藏不达标结果。

## 待确认/风险清单

- 灰度功能、组织策略和会议主持人设置可能使可用用户面受限；用户身份授权不等于所有会议可读，也不等于可绕过会议知情/隐私要求。上线前明确参会者告知、数据最小化、保存期限、撤销授权和删除机制。
- 员工说明没有给出事件留存、游标语义、实时字幕生成前置条件及端到端 SLA；这些都须通过文档 + 实测确认。即使用户 token 路线不会显示“机器人入会”，也需产品上明确助理正在读取会议内容。
- 如果用户没有参会或会议未启用相关能力，应明确不可用，不静默切到本地录制 hack；备选路线须单独获得用户确认及合规评估。

## 工作顺序变更

1. 文档/权限/灰度核验 + 真实会中最小 curl/脚本验证；留下脱敏证据和不可用原因。
2. 通过后实现官方字幕源及自动化测试，接入上下文/唤起/输出，完成端到端计时。
3. 仅在官方路线受限或质量/时延不达标时，恢复现有 `.vemedia` + STT 的会中性能对比及云端 STT 开发；会后妙记仅用于经授权的补全/核对。
