## 阶段 0：接口与准入验证（阻塞后续开发）

- [ ] **0.1 核对官方接口契约。** 留存 `user_active_meeting`、`bots/events` 的准确文档链接、核验日期及版本；核对 URL、请求/响应字段、`transcript_received` 结构、所需 token 类型和权限、分页/空页/游标语义、事件留存、限流、错误码、会议结束行为。产出：可追溯的契约记录；不以页面可访问或 HTTP 200 代替内容验证。
- [ ] **0.2 打通测试应用授权。** 申请并确认最小权限 `vc:meeting.meetingevent:read`、可能的管理员/用户授权要求；取得用户 `user_access_token`，验证过期及刷新流程。产出：仅在本地安全配置使用的凭据和脱敏的授权步骤，不提交 token。
- [ ] **0.3 核验会议准入条件。** 测试用户本人参会、“允许智能体入会”开关、可能的“AI 总结”依赖、客户端版本/灰度、主持人与组织权限；记录不可用时的明确提示。产出：目标试用群体可复现的启用步骤及阻塞清单。
- [ ] **0.4 完成获同意的双账号会中最小验证。** 用参会者 A 的用户 token 获取内部 `meeting_id`（非 9 位会议号），会中拉取并筛出新 `transcript_received`；核对说话人、文本、语言、起止时间、`sentence_id` 的实际字段/类型/单位/缺失情况。测试本人未入会、无开关、无权限、token 失效和切会；保存必要的脱敏样例及可复现结果。
- [ ] **G0 决策。** 只有目标用户可完成准入、会中可稳定取得新句子时才进入阶段 1；否则记录失败原因，单独评估 v1 路线及其合规要求。

## 阶段 1：最小增量采集器（G0 通过后）

- [ ] **1.1 设计 `MeetingTranscriptSource` 与事件语义。** 定义启动/停止、会议 ID、确认字幕、状态及错误输出；与 v1 下游语义可对接。官方字幕暂按确认句处理，不假造 `partial`；若实际提供修订再设计更新规则。
- [ ] **1.2 实现会议发现与生命周期。** 识别加入、离开、结束及切会；不同 `meeting_id` 隔离游标和去重状态。
- [ ] **1.3 实现分页和游标。** 基于 0.1 实测/文档确定首次启动、空页、续页、重启及游标过期行为；按接口顺序处理，成功交付后再提交游标。设计幂等键（优先会议 ID + `sentence_id`，必要时结合实际事件字段），避免重试导致重复或漏句。
- [ ] **1.4 实现轮询和异常处理。** 区分追赶分页与无新事件时的可配置轮询间隔；遵守限流；429/5xx/网络异常退避，401/403 停止无效重试并提示重新授权，游标过期报告缺口。不把聊天、进出事件当字幕。
- [ ] **1.5 加入脱敏可观测性及安全保护。** 记录请求耗时、轮询间隔、最近字幕年龄、重复/缺口、错误及会议切换；不记录凭据或未经授权的完整会议内容。
- [ ] **1.6 自动化测试与会中回归。** 使用脱敏 fixture、假客户端和可控时钟覆盖分页、空页、重复、乱序/修订、缺字段、重启、限流、token 失效、游标过期、切会；在授权真实会议中核对增量输出，不只凭模拟响应判定通过。

## 阶段 2：实时问答与验收

- [ ] **2.1 确认首版交互及验收口径。** 与产品确认临时方案“用户明确唤起 + 独立界面文本回答”，以及 6 秒目标的统计口径（尤其样本量、P95）、授权和参与状态展示。
- [ ] **2.2 接入上下文、唤起与回答。** 支持确认字幕进入上下文、结论修正、暂停/恢复/取消；不被唤起时不回应，内容不足时说明不确定性。
- [ ] **2.3 实测会中延迟与完整性。** 多场获授权会议包含远端发言；标注提问结束、字幕可用、接口请求/返回、Agent 开始有效回答的时刻并说明时钟误差。对比合规轮询间隔下的中位/P95/最大时延与漏句，检查长句、术语和中英混说。
- [ ] **2.4 完成安全和隐私审查。** 明确参会者告知、授权撤销、资料访问、最小化采集、保存期限和删除方式；无权限或无字幕能力时明确报不可用，不静默切换到本地录制。
- [ ] **G2 验收/回退决策。** 依据已确认口径检查准入、无不可解释漏句、6 秒端到端目标和隐私要求；若不达标记录字幕生成/轮询/模型各段瓶颈，再决定优化、经单独确认启用 v1 + STT，或调整产品目标。妙记接口仅考虑经授权的会后核对。
