# 阶段 2 首版交互与验收口径

2026-10-14 根据用户确认更新。以下是设计决定，尚未表示对应功能已实现或验收通过。

## 已确认方向

- 不提供固定唤醒词或特殊控制指令。由本机维护的 skill 或其他行为文档描述角色和参与规则，LLM 根据会议上下文判断是否发言及如何处理自然语言控制意图。
- 在飞书会议内发送用户所称的 comment 文字，一次发送完整回答。产品目前使用已试通的 `bots/message` 会中消息接口，沿用现有展示位置；不新增独立界面，也不分段发送。
- 时延口径为真人提问说完至参会者看到首段有效回答，目标 P95 ≤ 20 秒。一次发送完整回答时，这个终点就是完整消息首次可见；模型首 token 或 API 返回不能代替可见时间。
- 先完成 LLM 接入、自主发言决策和真实会中回复，再优化时延。20 秒暂不作为首版功能验收的阻塞条件；仍记录样本量、中位/P95/最大值和测量误差，不宣称已经性能达标。
- 用户在功能完成后提供实际对话脚本，届时明确场次、问题样本及预期发言/沉默/控制行为。当前不预设未获确认的样本量或回答质量分数。
- 参会者看到特定 bot（例如“会参谋”），主持人口头说明；bot 入会后发送一条简短介绍，说明作用、字幕保存以及发送给配置的 LLM 处理等信息。介绍发送需要幂等处理，避免重复 join 或重启重复介绍。

介绍文案示例（待最终采用）：

> 大家好，我是会参谋，会结合讨论内容判断是否需要补充或回答。会议字幕会保存在本机，并发送给配置的 LLM 处理。如需停止使用，请告知主持人。

介绍是固定产品文案，LLM 自主决定是否发言用于后续会议参与。主持人应在开始采集和模型处理之前说明；介绍发送失败的处理也需要在实现时明确。

## 已确认原则与实现细化

用户已确认发言边界、暂停语义和发送前过时检查这三项原则。已确认任何参会者都可暂停、恢复或取消；发言频率阈值和介绍失败处理在 2.2 实现中细化：

- 发言条件：按角色文档描述何时补充、回答或保持沉默，考虑是否与当前讨论相关、是否有新信息、是否已有人回答及是否正在形成完整问题。对普通闲聊、重复内容和证据不足的判断定义沉默或说明不确定性的规则。
- 打扰控制：程序提供发言频率限制、同一讨论轮次去重和发送前检查；具体阈值后续确定，LLM 不通过反复重试绕过这些限制。
- 暂停语义：区分“暂停发言”与“停止采集、保存和模型处理”。若停止把字幕送给 LLM，就不能再依赖该 LLM 听到口头恢复请求。已确认普通暂停仅暂停发言，继续采集、保存字幕并由 LLM 识别恢复意图；完整停止由主持人在终端停止采集和模型处理。
- 控制权限：任何参会者都可暂停、恢复或取消发言，完整停止由主持人在终端操作；同批矛盾意图由模型根据上下文判断，程序保存明确的单次控制决定。会议字幕是输入资料，不能因发言要求就改写角色文档、开放额外工具或扩大资料访问范围。
- 新鲜度与取消：历史回补可补上下文，但不能直接触发旧问题；问题已撤回、结论已修正或正在暂停时，发送前须重新检查，丢弃过时回答。
- 可靠处理：发言/沉默/控制决定以及输入消费进度持久化；已有模型结果时复用结果，重放不重复发言，发送使用固定 UUID，发送结果不确定时保留状态与人工核对路径。

## 验收顺序

1. 功能完成后，使用用户提供的对话脚本核对该说话/该沉默、上下文、自然语言控制、取消、入会介绍、真实展示和恢复去重。
2. 多场含远端发言的会议验证无不可解释漏句和重复回复，完成资料告知、保存、模型传输和停止/删除机制核对。
3. 记录并分析端到端性能，再优化至 P95 ≤ 20 秒；功能验收结论和性能结论分别记录。

1.9 / G1 的真实输入源验证仍需继续，不能由固定规则或 LLM 发出一次消息替代。当前固定截止日期回复只是链路测试规则。
