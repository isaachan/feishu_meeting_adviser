# 模型回答发送渠道

`notifications` 只控制真实模型生成的完整回答；固定规则测试后端仍只发送会中消息。省略本节时保持原有会中发送。可单独启用会中消息、定向飞书单聊，或同时启用两者；至少启用一个目标。

```yaml
notifications:
  meeting_comment: true
  recipients:
    - "ou_xxxxxxxx"
```

`recipients` 只能填写当前应用的用户 `open_id`，最多 20 个，不允许重复。不要填写会议中的显示姓名、邮箱或会议字幕里的说话人 ID。机器人使用应用身份的 [IM 发送消息接口](https://open.feishu.cn/document/server-docs/im-v1/message/create)向用户单聊发送文本；它与[会中消息接口](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/vc-v1/bot/message)是两个渠道。应用需要 IM 机器人发送权限（例如 `im:message:send_as_bot`），目标用户也需处于应用可用范围内。接收人可以不在会议中，因此主持人应事先确认其有权接收会议回答。模型回答可能包含字幕及日程材料信息。

会中消息和每个单聊分别保存 UUID、渠道、目标和发送状态；同一回答只调用一次模型。成功的目标重启后不再重发。权限拒绝等明确错误保留为 `rejected`；超时、连接中断或返回异常保留为 `uncertain`，不自动重试。查看 `replies` 的每条目标记录，在会议或相应单聊核对后，按该记录的 UUID 使用 `resolve-reply --outcome sent|retry|cancel`。`replies` 默认不显示正文，目标 ID 只显示末尾六位；`--show-text` 会显示回复正文。某个目标失败不会自动转发到其他渠道，也不阻止其他目标的发送。

发送前仍对每条待发记录检查当前会议、字幕积压、暂停状态、证据和材料版本。若回答在发送过程中被新字幕、修订或控制决定取代，尚未发送的目标可能被取消；已经发送的消息不会撤回。普通回答的发言间隔作用于不同回答，同一回答的多个目标可以连续发送。改变配置后需重启 `consume`；启动时会取消已从配置中移除的待发目标，新增目标只用于以后生成的回答。关闭 `meeting_comment` 后不会在会中发送机器人介绍，主持人的口头告知仍然必要。

本机 `adviser.sqlite3` 从 v2 到 v3 的升级在下次 `join`（启用会中介绍时）、`collect` 维护或 `consume` 初始化时进行，原有会中回复记录按会中目标保留。只读的 `status`/`replies` 不执行数据库升级。使用权限受限的本机配置和数据目录，不把接收人 ID、正文或凭据写入诊断与仓库。

自动化测试覆盖配置校验、API 请求格式、会中与多人单聊同时发送、部分结果不确定、重启去重、移除接收人和 v2 数据库升级。真实单聊权限与展示效果需要在获授权的测试用户上核对；本次实现未发送真实消息。
