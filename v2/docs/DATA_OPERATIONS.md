# 产品资料与诊断

应用凭据只读取本机 YAML，tenant token 仅在内存中，不保存应用密钥或原始 API payload。2026-10-15 新增的用户 OAuth 凭据按明确授权单独私有保存，规则见下文及 [USER_OAUTH](USER_OAUTH.md)，不写诊断。规范化字幕、说话人及会议/句子标识是敏感资料，保存于私有 `data/source.sqlite3`；产品 session 也在该数据库中，独立于 spike。目录为 `700`，数据库、WAL/SHM 及诊断文件为 `600`。仅支持本机文件系统的 POSIX 锁和 SQLite，不在共享网络盘运行。同一应用共用一个产品数据目录，操作锁在该目录内协调。

用户 OAuth 当前 access / refresh token、scope、有效期与状态保存在独立 `data/oauth/<应用标识hash>.json`，目录 700、文件 600，原子替换并同步落盘。用户标识只保存为 hash，不保存用户信息接口返回的姓名、邮箱或电话，不保存授权码、PKCE verifier 或回调 query。刷新前先保存 refreshing 标记并移除旧 token 字段，未知请求结果 / 中断不会重用一次性 refresh token，需重新授权。认证文件属于跨会议的共享凭据，`delete-meeting-data` 不删除；单独执行 `python -m feishu_meeting_adviser.oauth logout` 删除本机凭据，远端授权在飞书侧撤销。它不按会议资料的 7 天保留门槛自动删除。

默认内容预算 100 MB，SQLite 主库分配预算 150 MB（每个源/假消费者/模型消费者数据库分别限制）；WAL 自动检查点和日志大小限制控制额外占用，`status` 显示主库及侧文件实际大小。这不是整个数据目录的磁盘硬配额；保留足够的磁盘空间。内容、页分配上限或磁盘空间耗尽时事务回滚，检查点不推进；无法落盘的故障由退出码及安全终端提示报告，不伪称诊断已经可靠保存。默认每份诊断最多 1 MB，保留当前文件和 3 份备份，降低配置上限时同步清理超额诊断。

诊断采用字段白名单，仅含状态、错误分类/数字代码、请求标识摘要、请求与处理耗时、重复/修订/冲突计数、积压、容量及时间差汇总。请求标识保存摘要，不保存服务端 msg、正文、参与者、会议 ID、token 或原始查询。每页事务提交后单独记诊断；日志故障不会删除已提交输入。首次出现的字幕/修订候选才进入接收差值统计，重复扫描不重复计样本；回补样本按扫描模式区分。事件接收差值、发言结束至接收差值、最近字幕年龄是三个指标，负值保留以暴露时钟偏差；均不能替代真人说完至看到回答的时延。

默认 7 天为历史记录的可清理门槛。自动维护每分钟检查：只清理超过期限且所有已注册消费者都确认的交付，保护未确认输入、未解决冲突和活动会议恢复/去重状态；过期历史已被裁剪会产生持久化提示。已确认离会、超过期限、全部交付已确认且无未解决冲突的会议可整体清理，其假消费者副本也删除。离会记录按会议保存，切换新会议不丢旧会议的清理依据。

未消费资料与仍需恢复的活动会议状态不会在第 7 天强制丢弃，可能继续占用容量直至消费、离会或显式删除；容量耗尽时停止推进检查点，不能用无声丢弃解决积压。删除中断后，持久化删除标记会在后续维护中继续清理假消费者副本。

从 `v2/` 执行：

```bash
.venv/bin/python -m feishu_meeting_adviser status
# 采集时显式显示新入库字幕、说话人和时间；不确认消费。
.venv/bin/python -m feishu_meeting_adviser collect --show-text
# 手动维护前先停止 collect 与 consume；正常采集会自动维护。
.venv/bin/python -m feishu_meeting_adviser prune
# 默认只列未解决候选的交付哈希；下条命令明确在本机显示候选正文。
.venv/bin/python -m feishu_meeting_adviser conflicts
.venv/bin/python -m feishu_meeting_adviser conflicts --show-text
.venv/bin/python -m feishu_meeting_adviser resolve-conflict --delivery-id <候选交付哈希>
# 先停止 collect 与 consume；删除当前会议的输入、消费进度和所有托管消费者资料，不可恢复。
.venv/bin/python -m feishu_meeting_adviser delete-meeting-data --confirm
```

显式删除不受“未确认”保护规则限制；产品保留必要的 bot 控制 session，以便显式离会，但已删除会议不能自动重采。删除标记只保存会议标识摘要与删除时间，不保存正文。SQLite 启用安全删除并在显式删除后压缩/截断 WAL；这是应用数据清理，不承诺存储介质物理擦除。手动备份、终端正文、其他自建消费者和 spike 的 `output/` 不属于产品托管副本，应另行按授权清理。撤销授权时先停止模型消费和采集，按需要显式离会并删除资料。

`consume` 的截止日期测试规则将待发送回复正文、固定 UUID 和发送状态保存在同一私有消费者数据库的 `rule_replies` 表中；正文不进诊断。会议整体清理或显式删除会同步清除这些记录。删除本机资料不能撤回已经发送到会议的消息。

阶段 2 的消费者资料保存于私有 `data/adviser.sqlite3`：规范化输入副本、会议上下文、活动模型任务快照、已完成决策与证据摘要、参与状态和回复队列。采用与源相同的访问权限、SQLite 页容量约束和内容预算。完成的任务不反复保存整份 prompt；输入副本/完成任务/普通回复在超过保留门槛且无未处理任务或未解决发送时可清理，活动会议上下文及介绍去重身份保留至会议整体清理。

待模型处理输入、待发送/不确定/拒绝回复保护自动整体清理，不因源已确认就删除；可能超过默认 7 天，直至处理、核对或显式删除。显式删除需停止两个进程，覆盖源、假消费者和 adviser 数据，保留 bot 控制会话以便离会。Codex 每次决定使用 ephemeral 线程，完成后 unsubscribe，重启依赖产品数据库；不会通过复制全局 Codex 登录资料建立项目缓存。供应商侧数据以及已经发出的会议消息不属于本机删除范围。

诊断新增模型耗时、决策保存、参与状态和发送确认等白名单字段，不记录模型 prompt、字幕、回答或任意服务端错误文本。

模型诊断另包含调用阶段、该阶段耗时、推理强度和 MCP 服务状态计数；目录计数可能来自缓存，不等于可调用工具数。服务/工具名称、URL 及配置正文不落诊断，消费者再次按白名单筛选后写入。定位步骤与已核查证据见 [MODEL_DIAGNOSTICS](MODEL_DIAGNOSTICS.md)。

## 日程材料与内容预览

2.5 材料快照保存在 adviser.sqlite3 的 meeting_materials 表，包含显式日程/实际入会绑定、读取身份摘要、来源、正文范围、时间和稳定 context_version。模型任务与待发回复保存所用版本；完成任务压缩为证据摘要。材料占用消费者内容预算，活动会议快照随会议整体清理或显式删除；活动任务和未解决发送继续受恢复保护。

consume 每次启动读取时，终端显示内容预览，另存私有 `data/content_previews/<会议标识hash>/materials.jsonl`，默认每文件 1 MB，当前文件加 3 个轮转备份。描述和正文最多 2000 字符，保留原长度；引用/附件列表有数量上限，缺字段、空、失败、未支持及截断分别记录。这些是含正文的资料日志，与白名单脱敏 diagnostics 分开，不能当作公开诊断分享。它只保存程序构造的材料字段，不保存原始响应、认证头或 token。

内容预览按文件最近写入时间执行同一 retention_days 门槛，不会因删掉预览而删掉活动任务依赖的材料快照；显式 delete-meeting-data 同步清除该会议的日志与快照。恢复用空锁目录保留，但无正文。共享 OAuth 凭据和一次性 context_probe 报告不在会议删除范围，分别 logout / 手动清理。终端副本与供应商数据仍需单独处理。

首版只在 consume 启动时读取：权限撤销、文档更新不会在当前启动快照中实时同步。撤销授权时先停止 consume；下次读取失败会清空可用缓存并阻止新的模型回复。更换账号由用户身份摘要检测并停止消费，要求核对绑定后重启。
