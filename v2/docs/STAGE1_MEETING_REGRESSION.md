# 阶段 1 真实会议回归（执行中，未验收）

以下为操作步骤及未验收的进展记录。至少两场新增会议，可与 TODO 0.6 合并；每场包括本机和远端发言。先确认参会者同意、主持人已打开阶段 0 需要的会议设置、本机配置会议号正确，以及旧 spike bot 已离会。凭据和会议号只保留本机，不在聊天或报告中发送。

## 每场步骤

1. 从 `v2/` 使用产品 `join`，再启动 `collect`。使用 [双人脚本](TRANSCRIPT_TEST_DIALOGUE.md) 或同等可逐句核对的合成对话，每轮记说话人标签、真人说完时间和时钟校准误差。
2. 正常说话期间在终端 B 调用 `transcripts --show-text` 查看最近字幕的正文和说话人，再调用 `status` 查看状态与积压，在另一个终端调用 `consume`，直到待消费数量归零；消费只写假消费者，不调用 LLM、不发消息。连续观察至少 10 分钟及一段安静期，记录空页和是否触发真实分页。
3. 停止采集，远端继续按脚本说几句，随后重启 `collect`；观察旧检查点、未确认输入和停机期间字幕的回补。恢复后仍有完整性风险提示是预期行为，需要人工对照证明该区间齐全。
4. 由操作者在合成测试期间安排一段可控断网，记录起止时间，远端继续发言；恢复网络后核对采集自动恢复、回补与重复。断网操作会影响本机会议连接，须由操作者掌握时机；自动化故障测试不能替代这一项。
5. 停止采集，消化剩余积压，显式 `leave`；核对远端看到 bot 离会。另观察会议实际结束后的事件/错误行为，不用空页推断结束。更换会议后重复上述步骤，检查数据隔离。
6. 本机对照源数据库、假消费者上下文和人工记录，不把正文或身份复制到聊天。按资料管理策略清理测试资料。

## 脱敏记录

每场只记录匿名场次/参会者标签、发言轮数/可对应轮数、无法解释的漏句、重复添加上下文数、说话人错误、修订/冲突、请求与分页统计、停机/断网区间及恢复结果。时延分别报告发言结束至接收差值的样本量、中位/P95/最大值，以及人工计时/时钟误差；不能将它称为端到端回答延迟。

真实多页、token 到期、游标失效等没有触发时写“未覆盖”，不能用假客户端结果替换。会议结束信号若没有明确语义，报告未知状态及人工确认结果。对照发现疑似漏句时保留本机资料排查，只提交脱敏原因与结论。

全部结果齐全后更新 1.9，并另做 G1 决策；20 秒目标和真实问答仍属于阶段 2。
