# 飞书实时会议 AI 助理 — PRD

版本：0.1（需求草案）  
日期：2026-10-08

## 产品定位

[KNOWN | HIGH] 本产品面向飞书会议，目标是让 AI Agent 在会议进行期间理解讨论、回答问题并提供有用的补充。实时参与是核心要求，会议结束后才提供总结不能满足这一目标。

[INFERRED | MED] 以下功能与范围是依据该目标整理的需求草案，供产品评审；尚未约定的交互方式和指标列为待定项。本文件只描述业务需求，不判断技术可行性。

## 用户与场景

[INFERRED | MED] 初期服务于项目会议、需求评审和技术讨论中的主持人及参会者。主持人需要把握议题和结论，参会者需要及时查找资料、澄清问题，减少为查证信息而暂停讨论的情况。

| 场景 | 助理应提供的帮助 |
| --- | --- |
| 讨论中询问一个问题 | 结合当前议题回答，必要时向提问者澄清 |
| 需要确认已有资料或历史决定 | 从获准使用的资料中查找，并给出可核对的出处 |
| 讨论出现分歧 | 整理各方观点、分歧点与需要确认的问题 |
| 主持人要求收束议题 | 汇总当前结论、未决问题和下一步行动 |
| 用户中途加入或漏听 | 按需说明此前讨论进展 |

[INFERRED | MED] 上表为建议场景，不代表已验证的用户需求。

## 核心体验

[INFERRED | MED] 用户在会前启用助理并选择可使用的资料；进入会议后，助理持续跟进讨论。参会者可以明确唤起助理提问，助理依据当前上下文作答。主持人可以随时暂停助理、要求简短回答或结束参与。

[INFERRED | MED] 首版建议优先采用“用户主动唤起、助理回应”的方式。自主插话作为后续能力评估，以减少对讨论节奏的干扰。

## 功能需求

| 优先级 | 功能 | 业务要求 |
| --- | --- | --- |
| P0 | 实时理解 | 在会议仍进行时跟进最新讨论，识别当前问题和议题 |
| P0 | 实时问答 | 被唤起后给出与当前讨论相关的回答，不要求会议结束 |
| P0 | 上下文连续 | 理解此前已讨论的内容，并在结论被修正时更新理解 |
| P0 | 参与控制 | 支持启用、暂停、恢复和结束；参与状态清晰可见 |
| P0 | 明确不确定性 | 无法听清、资料不足或答案存疑时明确说明，并按需澄清 |
| P1 | 资料辅助 | 使用用户授权的会议资料回答，并提供出处 |
| P1 | 即时梳理 | 按需整理进展、观点、结论、未决问题与行动项 |
| P1 | 会后回顾 | 形成可核对的会议回顾，区分已确认决定与建议 |
| P2 | 主动提醒 | 在用户允许的范围内提示遗漏、冲突或待确认事项 |

[INFERRED | MED] 上述优先级为首版范围建议。会后回顾是辅助功能，不能替代实时参会验收。

## 首版范围与边界

[INFERRED | MED] 首版建议围绕单场会议完成“启用—跟进讨论—被唤起—回应—暂停或结束”的完整体验，先验证实时问答的价值。首版不要求同时处理多场会议，也不要求自动代替用户作出决定或执行会议中提到的业务操作。

[INFERRED | MED] 助理应让参会者知道其参与状态及信息使用范围。行动项、负责人和截止时间应以会议明确表达或用户确认的内容为准；资料与会议内容的保留、访问和删除规则需要在上线前确定。

## 验收与成功指标

[INFERRED | MED] 首版至少应演示：会议进行中提出一个依赖刚才讨论的问题，助理及时作答；会议修正前面的结论后，助理按新结论回应；暂停后不再回应，恢复后可以继续参与。会后才生成结果的演示不计为实时能力通过。

| 指标 | 业务定义 | 当前状态 |
| --- | --- | --- |
| 响应时延 | 从用户提问结束到开始提供有效回答的时间 | 目标待定 |
| 回答有效率 | 用户认为回答解决问题或推进讨论的比例 | 口径和目标待定 |
| 上下文准确性 | 能否正确引用当前议题及已更新的结论 | 评测样例待定 |
| 干扰程度 | 无关回应、误触发或不合时宜的插话次数 | 目标待定 |
| 使用意愿 | 用户是否愿意在后续会议继续启用 | 试用后评估 |

[INFERRED | MED] 上表为建议验收维度，不代表已达成的性能承诺。
