# 产品需求 · v0.3（草案）

状态：设计基线，随实现冻结。人物与场景是本文的核心；实现细节见 [ARCHITECTURE](ARCHITECTURE.md)。
修订：v0.2 重写 S1 为"bot 指令驱动"流程（OAuth 上云、命令下发、自动 consume）；v0.3 评审修订：删除暂停/恢复辅助、订阅 revoked 定为终态、draining/ended 拒新订阅、命令模板修正（mic 默认关、明文 ws）、授权链接统一经 advisor 下发、材料来源定为建会时从日历事件描述自动带出。

## 1. 产品定位

会参谋在会议进行中为**组织者**提供实时辅助（听会 → 理解 → 判断是否需要补充或回答），并按组织者的**显式授权**把辅助结果分发给参会者。组织者是会议数据的拥有者：录音、字幕、AI 回答的可见范围由组织者一人决定。

## 2. Personas

### 小A —— 会议组织者（主持人）

- 有飞书账号；目标会议在她的日历上，且**她是该日历事件的组织者**（准入校验条件）。
- laptop（Mac 先行，Windows 跟进）上装两个东西：飞书客户端、会参谋采集器（recorder）。采集器**零配置、零凭据**，只按命令执行。
- 首次使用时在飞书里点一次授权链接完成 OAuth（凭据保存在云端，此后自动刷新，免打扰）。
- 对会参谋的所有操作都通过**与 bot 私聊**完成：入会、结束、审批、撤销。
- 期待：开会时像带了一个不出声的参谋，该提醒的提醒、该回答的回答，都发到飞书私聊里。
- 权限：批准/拒绝参会者的订阅申请；随时撤销订阅。

### 小B —— 普通参会者

- **只装飞书，什么都不装**，不部署任何东西。
- 通过与"会参谋 bot"单聊表达诉求；收到的内容由小A 的授权决定。
- 明确不能做的事：驱动 AI（提问、改变模型行为）、获取授权范围之外的内容（如完整字幕、录音）。

## 3. Scenarios

### S1 · 启动一场会议（小A，含首次授权）

前提："会参谋"是已配置好的企业自建应用（bot 能力已开通）。

1. **指令**：小A 在飞书对会参谋 bot 说："你要入到这个会中，会议 id 是 123456789"（或直接发一个 `vc.feishu.cn/j/` 会议链接）。
2. **鉴权（仅首次或凭据失效时）**：bot 经 advisor 查云端是否已有小A 的有效授权；没有则 advisor 返回授权链接、由 bot 转发小A，小A 在浏览器（电脑/手机均可，需能访问部署网络）完成飞书 OAuth；user access token 保存到**云端**（按小A 身份隔离），此后 advisor 自动刷新。**小A 全程不接触 token 明文。**
3. **校验**：bot 背后的 advisor 用小A 的授权读取飞书日历，核对三点：会议存在、小A 是该日历事件的**组织者**、当前在会议时间窗内。任一不满足，bot 明确告知原因，不创建会话。
4. **建会与命令下发**：校验通过 → advisor 创建会话（顺带把校验时读到的**会议事件描述**存为该会话的背景材料；描述为空则无材料，不阻塞，小A 无需任何额外操作）并**自动启动 consume**；bot 把采集器启动命令发给小A，形如：

   ```
   recorder real --session <会话id> --event '<cal>/<evt>' \
     --url ws://<server>/<ingest> --token <流令牌> [--mic]
   ```

   命令中含云端分配的会话 id、日历事件 id、上行地址与**短期流令牌**（仅绑定本会话）；`--mic` 为本机麦克风的显式开关，**仅在小A 明确选择开启麦克风时**才出现在命令中（默认不出现）。
5. **执行**：小A 在 laptop 终端粘贴执行命令，采集开始：远端声音（系统播放回路）默认开启；本机麦克风默认**关闭**（隐私优先：小A 在飞书静音期间不该被录的话，不进链路）。整场原始音频本地留存（排障/重转写用），不上传。laptop 不保存任何用户凭据。

验收口径：未授权（拒绝授权链接）、非组织者、超时间窗、会议不存在——四种情形 bot 均拒绝并说明原因；下发的命令文本中**不得出现 user access token**。

备注：v1 命令为复制粘贴执行；"一键启动"（本地守护进程 + IM 内链接唤起）列为后续增强。

### S2 · 会中辅助（小A 的主链路）

1. 采集器把音频持续上行到云端 advisor（远端回路常开；本机麦克风开启时加一路；**每路一条独立连接**，每路约 32 KB/s，流令牌鉴权）。
2. 云端转写为字幕 → 进入该会议的会话上下文（字幕 + 建会时带出的会议描述材料）→ 模型判断是否需要发言。
3. 需要时，会参谋 bot 把回答（LLM reply）以飞书私聊发给**小A**。

验收口径：说完一句被回答的话 → 小A 飞书收到回答，全链路 P95 时延预算 ≤ 20 秒（由旧"15 秒字幕 + 5 秒 LLM"拆分预算合计而来，待端到端实测修订）。

### S3 · 参会者订阅（小B + 小A 审批）★ 核心新场景

前置：小B 在飞书里能找到会参谋 bot（应用可被发现/可添加）。

1. **申请**：小B 给 bot 发消息："你好，我想收到会议 123456789 的信息"。
2. **校验**：bot 解析 9 位会议号，在云端注册表里查找"正被服务中的会议"：
   - 命中且会话处于 `recording` → 生成订阅申请（状态 `requested`）；
   - 未命中 / 已结束（draining、ended）→ bot 回复小B"未找到该会议或会议已结束"。
3. **审批**：bot 给小A 发私聊："小B 请求接收会议《标题》的会参谋回答，回复『同意 #rN』或『拒绝 #rN』"。
4. **小A 回复**：
   - 同意 → 订阅置 `approved`，bot 回执双方；**从下一回答起**，小B 与小A 同时收到 LLM reply。
   - 拒绝 → 订阅置 `denied`，回执小B。
5. **撤销**：小A 对 bot 说"撤销订阅 <小B> <会议号>"→ 置 `revoked`，此后小B 不再收到。`<小B>` 为飞书昵称，bot 负责解析为用户；歧义或未命中时提示小A 用 `状态` 查看订阅列表后重试。
6. **重复申请幂等**：已 `approved` 再申请则提示当前状态，不新建；`denied` 后再申请需小A 重新审批（按新申请处理）；`revoked` 为**终态**，再申请不新建，bot 直接告知小B"该订阅已被组织者撤销"。

边界（显式约束）：

- **仅前向**：批准只对之后新产生的回答生效，不回溯历史回答。
- 小B 收到的是**会参谋的回答**，不是完整字幕或录音。
- 小B 的任何消息都不进入模型上下文、不触发模型调用。
- 审批请求不承诺可靠投递（bot 离线期间小B 的申请会丢，小B 重发即可）；已批准的分发走 outbox，可靠。

### S4 · 会中问答与控制（小A）

小A 对 bot 的指令集（v1 全部走私聊文本，规则解析、不进 LLM）：

- `入会 <9位会议号 | 会议链接>`（S1）
- `结束会议 [会议号]`（停止辅助，云端排空收尾；缺省作用于最近一场 recording 会话——v1 支持同一组织者多场会议并发）
- `同意 #rN` / `拒绝 #rN`（审批，#rN 为 advisor 全局分配的订阅请求编号）
- `撤销订阅 <小B> <会议号>`
- `状态`（列出全部进行中会话的采集/模型/订阅概况）

### S5 · 收尾与异常

- **正常收尾**：会议结束，小A 在终端 Ctrl-C 停止采集（或按时长自动停），并对 bot 说『结束会议』；云端把该会话排空（在途字幕、模型任务、待发回答全部落定）后置 `ended`。`ended` 后的新订阅申请一律拒绝。
- **网络断线**：采集器本地缓冲、恢复后重传；断线期间未完结的语句丢失（与旧 STT 契约语义一致）。云端对已收到的输入照常处理。
- **laptop 合盖/退出**：等同断线且不自动恢复；云端继续处理已收到的输入后排空。
- **云端不可用**：采集器本地持续留存音频（证据在手），字幕丢失不补（v1 不做事后重转写，列为后续增强）。
- **授权失效**：refresh token 过期时，bot 在下次需要校验前重新发授权链接，小A 点击后续接原意图。

## 4. 范围与非目标

**v1 范围**：S1–S5 全部；单云端部署（内网/受信网络）；同一组织者的多场会议并发；多个组织者共用部署（数据按用户隔离，鉴权为首日需求）。

**非目标（v1 明确不做）**：

- 小B 驱动模型（任何形式的问答）。
- 批准后回溯历史回答。
- 群聊内 @bot 问答（旧 chatbot demo 能力，不带入）。
- 暂停/恢复辅助（v1 不做；需要安静时直接 `结束会议`）。
- 即时会议（无日历事件）的采集与订阅。
- 多设备对同一会议双录、字幕合并。
- 公网匿名注册开放（部署受信边界内运营）。
- 录音/字幕的会后产品（妙记类能力）。
- 一键启动采集器（IM 链接唤起本地守护进程，后续增强）。
